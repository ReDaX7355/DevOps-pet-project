# Пет-проект "Обучение DevOps"

Этот проект предназначен для демонстрации навыков, полученных путем изучения методологии DevOps в системном администрировании.

## 0. Инициализация репозитория
Первоначально добавляю сюда мини-web-приложение, созданное с помощью ИИ, для дальнейшей работы с ним.

#### Описание веб-приложения
Это frontend-приложение "Todo", в котором можно добавлять задачи в базу данных Postgres через backend NodeJS.

**Состав проекта**
- Frontend: React Vite + Tailwind
- Backend: NodeJS + express
- DB: Postgres
- Nginx — реверс-прокси для приложения

## 1. Создание Docker-конфигураций
Далее создаю Docker-файлы для каждого сегмента приложения (Frontend, Backend). Для DB не создается Dockerfile, создание контейнера производится в общем конфиге docker-compose.
Он как раз создан для разворачивания всего приложения сразу.

Добавил проксирование через отдельный контейнер Nginx, конфигурация "nginx.conf" находится в главном каталоге.

## 2. CI/CD GitHub Actions
Добавил workflow для сборки образов backend и frontend и пуша их в GHCR (GitHub Container Registry).
Затем добавил deploy workflow, который следит за пушами в ветку main и сразу деплоит приложение на указанный сервер в секретах ниже.
 
#### Настройка секретов GitHub
Для работы workflow необходимо добавить Secrets в репозиторий:
- SERVER_HOST — IP или hostname сервера.
- SERVER_USER — пользователь SSH.
- SSH_PRIVATE_KEY — приватный ключ для доступа по SSH.
- POSTGRES_DB — имя БД в Postgres
- POSTGRES_USER — имя пользователя БД Postgres
- POSTGRES_PASSWORD — пароль пользователя БД Postgres
- DATABASE_URL — строка подключения к PostgreSQL.
- PORT_BACKEND — порт запуска backend.
Workflow автоматически подставляет их при сборке и деплое.

#### Использование
1. Пушим изменения в ветку main.
2. Workflow соберёт образы и обновит контейнеры на сервере.
3. Проверяем работу приложения через Nginx:

http://SERVER_IP/      → фронтенд
http://SERVER_IP/api/  → backend API

Далее настроил CD (dev-сценарий): я эмулировал деплой как на обычный сервер — через docker pull и docker compose up -d, без зависимости от наличия кода проекта на сервере.
Отдельно продумал прод-сценарий с self-hosted runner, который не удалось реализовать из-за отсутствия внешнего IP, но конфигурация под него подготовлена.

В процессе решил проблемы с:
- регистром имени репозитория для GHCR;
- рассинхроном package.json и package-lock.json;
- передачей переменных через Secrets;
- структурой Dockerfile и путями к src;
- триггерами workflow по веткам.

## 3. Мониторинг
Создал каталог "monitoring" с конфигурацией мониторинга Prometheus + Grafana, который собирает метрики контейнеров и системных ресурсов на сервере.
Все также разворачивается с помощью docker-compose.

#### Стек мониторинга
Для организации мониторинга используются следующие образы:
- Prometheus - основное хранилище метрик
- Promtail - чтение и сбор логов системы
- Loki - хранение системных логов и их отображение
- Grafana - вывод метрик в графики и дашборды
- cAdvisor и node-exporter - Сбор статистики docker контейнеров и ресурсов системы

В конфигурации также хранится список подключений для Grafana и готовые дашборды, взятые с общего хранилища Grafana dashboards.
Так что все работает "из коробки".
